# Language & linguistics

## What is language and linguistics

Language and linguistics terms are the vocabulary for talking about languages themselves: how they are classified and coded, how they vary, who speaks them, and how threatened they are.

One distinction runs under the whole cluster: a [language](language.md) is not the same thing as the [script](../writing-systems-and-scripts/script.md) it is written in, and it is not the same thing as a country or a locale. A language is spoken or signed; writing is a separate layer added on top of it. The same language can be written in more than one script, and one script can write many languages, so the [writing system](../writing-systems-and-scripts/writing-system.md) that pairs a language with a script is its own thing again.

### Why it matters

Two themes run through this cluster for product and design work.

First, languages are communities of people, so naming, representation, and support are matters of respect, not just data. Showing a language by its own name (its [autonym](autonym.md)) rather than an outsider's [exonym](exonym.md), and treating an [endangered language](endangered-language.md) as worth supporting rather than a rounding error, are design decisions with real weight.

Second, the facts here are easy to get wrong and consequential when wrong. Speaker counts, endangerment status, and language boundaries belong to specialists and to the communities themselves, so these terms give you a careful way to talk about them. Being precise about language versus script versus locale is also what keeps "languages supported" from silently turning into "which scripts we happen to render."

#### Example

Serbian is one language written in two scripts, while spoken Mandarin and Cantonese are separate languages that historically shared one written form. Neither fact makes sense if "language" and "writing" are treated as the same thing, which is exactly the confusion this cluster exists to clear up.
